# 参考演示风格技能 — v2 中文版

## 仓库分发方式

本目录保存 v2 技能源码。先安装 `requirements.txt` 中的依赖，再运行
`python scripts/build_templates.py`，即可生成下文对应的六份 Office 文件。
若没有可选的 v1 PPTX，脚本会根据仓库中的 JSON 重建几何蓝本；生成过程无需
原始演示、字体文件、网络调用或私人资料。仓库不提交位图预览；请使用生成的
版式标注 PPTX 与 `templates/layout-index.json` 选择版式。GitHub Actions
构建工作流运行时会将生成的模板上传为可下载的构建产物。

## 用途与边界

复用参考稿的视觉语言，而不是照搬其主题、内容或固定的 20 页结构。
用户决定主题、受众、语言、页数和顺序。重排现有演示时，除非得到改写授权，
必须保留原意、术语、数字、限定条件及要求保留的页面顺序。
不得为了填满版式而编造材料，也不得为了版面整齐而删掉关键证据。

本文件可独立使用。需要更准确复现版式时，同时使用 `templates/` 中的中文空白模板。
对应英文技能文件为 `SKILL.md`；两份文件说明的是同一套设计系统。

## 先确定制作模式

**空白模板模式：**保留卡片、分隔线、强调色条、箭头、表格网格及字体设置，
但清空示例正文、品牌、日期、页码和来源文字。每个内容区使用可编辑占位符，
位置、宽高、字号及颜色预先确定。填写提示放在版式或备注中，不作为正式内容显示。
随附空白文件第 01—13 页没有可见文字；最后一页仅预置通用致谢与交流邀请。

**正式演示模式：**把用户的真实内容填入合适的版式。14 种版式是可选库，
不是强制页数或顺序。新建演示通常在正文末尾加致谢页，除非用户指定另一种结尾。
仅重排且要求保留页数、顺序时，不擅自增加致谢页。

**版式标注模式：**用标注版展示字段位置、用途和层级。标注文字不是正式演示内容；
不要把标注版误当作已清空正文的模板交付。

## 快速工作流程

1. 明确模式、受众、输出语言及内容依据；不要再次询问已给出或可从材料读取的信息。
   未获授权时，不自行补充外部研究，也不悄悄改写用户的框架。
2. 选择语言和版式，优先复制对应的预制空白页面；也可从命名的自定义版式新建。
   不需要调整时，保持既定几何结构。
3. 填写正文以及需要的来源、品牌、页脚和页码。证据表格优先复制第 08 页，
   这样才能保留已经配置的原生网格与单元格格式。
4. 同时需要中英文时，制作结构对应的两份文件。翻译必须忠实，不能出现版本间的事实差异。
5. 致谢页置于正文末尾、可选附录之前。逐页渲染、检查换行与溢出，修正后再交付。

## 固定视觉系统

**画布：**13.333333 × 7.5 英寸，即 16:9，白色背景。
以 PowerPoint 文件中的实际尺寸为准，不能照搬可能被拉伸过的预览图片比例。

**层级：**蓝色主标题 → 灰色副标题或范围说明 → 细分隔线 → 模块化正文 →
可选结论条与来源说明 → 克制的页脚。封面和致谢页使用独立构图，不套用常规页眉。

**容器：**浅色、平面、柔和圆角，不使用阴影、浮雕、玻璃效果、渐变正文卡片或粗重边框。
保留外边距，让重复列与卡片严格对齐。蓝色为主，紫色和青色作为辅助区分；
不能只用颜色表达状态或结论。

### 各版式构建规则

**封面：**整幅浅色图片带为 `[0,0.70,13.333,4.60]`，左侧不透明白色面板为
`[0.52,1.45,8.05,3.55]`。v2 将可插入图片的占位区限定为右侧
`[8.74,0.70,4.593333,4.60]`，防止图片遮盖标题面板。
图片应裁切而非拉伸；未经授权，不带入参考稿原插图或标志。

**单栏内容：**浅蓝大面板为 `[0.58,2.12,12.17,3.93]`；小标题为
`[0.85,2.40,11.63,0.45]`，正文区为 `[0.85,3.05,11.63,2.65]`。
可放短文、经批准的图片或有真实数据的可编辑图表；模板本身不含任何数据。

**双栏内容：**横坐标分别为 0.58 和 6.82，纵坐标为 2.12，每栏为 5.93×3.93。
左浅蓝、右浅紫，顶部分别为蓝色和紫色细条。标题 24 pt，正文 19 pt；
两侧应采用可比的信息层级。

**三栏：**横坐标 0.58／4.74／8.90，宽 3.85，纵坐标 2.12，高 3.93。
顶部色条高 0.045，依次为蓝、紫、青；文字内缩 0.25。
按“类别→对象标题→证据→限制或门槛”排列。
比较、路线图、总结决策共享这一几何结构，但使用不同的语义字段。

**六卡：**列位置同三栏；两行纵坐标为 2.13 和 4.26，每卡 3.85×1.90。
顺序为序号、标题、两行简短说明。只有五项真实内容时，不能虚构第六项。

**结论条：**背景 `[0.58,6.20,12.17,0.43]`，蓝色粗体文字位于
`[0.79,6.27,11.75,0.30]`。一般只放一行，不可挤入来源说明区。

**流程与架构：**顶部七个简短步骤；左侧宽 6.081 的面板容纳四层白色结构块，
下方另设平台和依赖横条；右侧四组说明从横坐标 7.30 开始。
区分“系统做什么”和“人决定什么”。

**证据表格：**原生五列表格，蓝底白字表头，浅蓝／白色交替行，浅色网格，13.5 pt。
空白表不预先突出某些状态或行。第 08 张预制页包含完整格式的网格；
直接从该自定义版式新建页面时，只得到表格占位符，不会自动生成同样的单元格格式。
因此优先复制第 08 页；删掉不用的行，不能为了填满表格而编造数据。

**共享平台：**四个应用卡片位于浅紫色底座上方，底座内有五个白色能力块，
下方为浅青色输入／输出横条。连接线方向必须符合用户材料中的实际关系。

**流程与反馈：**保留顺序及反馈方向。不要为了适应窄框而把英文单词、
标识符或中文语义单位拆成不合理的多行。

**致谢：**不再放密集正文或决策卡片。浅蓝圆角面板为
`[0.58,1.80,12.17,3.55]`，顶部保留三条简短强调色线。
居中主标题为 `[1.20,2.68,10.93,0.92]`，交流邀请为 `[1.20,3.78,10.93,0.48]`。
中文预置“谢谢聆听”“欢迎交流与提问”；英文预置“Thank you”“Questions & discussion”。
面板下方的汇报人、团队、联系方式等字段在用户提供信息前保持空白。
致谢不能代替正文中有实质信息的总结与决策页。

## 中文本地化

未另行指定时使用简体中文。不仅翻译主标题，还要翻译副标题、字段提示、
卡片标签、备注、来源说明及结尾文案。产品正式名称、缩略词、技术标识符、
单位和数字如因翻译而改变含义，应保留原样。

采用自然中文，不机械沿用英文断行。中文正文使用适当的中文标点；
避免左括号落在行末、句末标点落在行首；数字与单位尽量保持在一起。
不要在每个汉字之间添加空格来模拟英文字体效果。

实用起点：30 pt 的单行主标题通常宜控制在约 28 个全角汉字以内；
窄三栏中 19 pt 正文每行可能只能容纳约 10—12 个全角汉字。
这是新增的排版建议，不是从参考稿测得的强制字数。
**实际渲染结果优先于字数估计。**未获改写授权时，改选更宽版式或拆页，
不能悄悄缩短事实。用户要求两种语言版本时，不要把完整中英文硬塞进同一文本框。

## 内容与密度

只有在提供的证据支持结论时才写结论式标题。保留范围、不确定性和重要限制，
明确区分事实、解释、提议与验收目标。不要沿用参考稿中的研究编号、历史日期、
价格、门槛、产品断言或品牌。

通常主标题和副标题各一行，小卡正文两行，高卡证据不超过四条简短文本。
十行表格只是容量，不是最低数量。实质性限定条件应出现在正文中，
不能藏在极小的来源脚注里。

内容放不下时，优先换版式、拆页，或把次要细节放入备注；
不能把关键限定条件一并移走。缩短必须不改变原意。
不得横向压缩字体，也不能拉伸整张幻灯片。

参考稿没有建立通用图表、动画或转场系统；新增图表样式必须标注为扩展，
不能说是原稿已有规则。图表应可编辑，数据有依据。未要求动画时使用静态页面。

## 构建与检查

从随附蓝本重新生成 v2 文件：

```bash
python -m pip install -r requirements.txt
python scripts/build_templates.py
python scripts/check_templates.py templates/blank-layouts-en.pptx templates/blank-layouts-zh-CN.pptx templates/reference-style-en.potx templates/reference-style-zh-CN.potx
```

旧脚本 `scripts/build_deck.py` 仍是 v1 的内容构建器，不负责生成 v2 自定义版式。
`references/template-workflow.md` 补充工作方法；`references/validation.md` 记录验证范围与限制。

交付前检查：模式与语言正确，画布确为 16:9，要求空白的字段没有正文，
结尾文案正确，原生占位符和表格仍可编辑，字体一致，无裁切或错位箭头，
来源有效，没有残留品牌。必须逐页查看渲染图，不能只看封面或缩略图。

本套模板使用 LibreOffice 渲染；没有单独在收件人的 Microsoft PowerPoint 上测试。
字体是否安装、后续输入内容长短都会影响换行。结构检查不能证明视觉适配或事实正确。
未测试的兼容性应明确说明，不能作无依据的保证。
