# Xiaohongshu technical long-form profile

Use for 小红书/Xiaohongshu technical articles. Default to Chinese and an
accessible engineer's deep dive; honor the user's language and scope. Apply the
core narrative-blueprint approval gate and the
[benchmark evidence workflow](benchmark-evidence.md). Do not substitute a short
promotional note for a requested full article.

## Blueprint and deliverables

Propose the thesis, full section plan, audience, evidence boundaries, figure
plan, delivery formats, and platform adaptation before drafting. Separate:

1. An editable, source-backed **mother draft** containing the complete approved
   narrative, quantitative content, caveats, and provenance.
2. A platform-ready long-form derivative, matching title and cover, captions,
   and optional short introductory note. A caption is not the full article.
3. Original figure sources plus rendered images, and a compact evidence/coverage
   companion. Adapt file formats to the user's tools; do not require a specific
   editor, cloud service, or browser automation provider.

Retain the intended artifact identity when revising editable files; create a
new copy only when requested or genuinely a distinct derivative. Name versions
unambiguously and record which draft/images the user approved. Deliver readable
files through native attachments when supported, with editable originals as
well as previews; a local path or inaccessible private URL is not delivery.

## Platform copy and visual checks

The default editorial choice for this profile is no external URLs, QR codes,
obfuscated links, or disguised off-platform redirection in the platform copy,
cover, or images. Keep source pins in the evidence companion and use readable
source/project names in prose. Honor an explicitly approved alternative after
checking current platform requirements. This is a profile default, not a claim
that the platform universally bans links or that a post cannot be throttled.

A gentle, optional Star invitation may name the project when relevant, e.g.
“如果这个项目对你有帮助，也欢迎给它点个 Star。” Do not add it when the user
has declined promotion; do not claim or promise traffic, safety, or reach.

- Design figures to explain the actual mechanism or data; do not fabricate
  benchmark plots, measurements, quality scores, or decorative technical labels.
- Render and inspect every delivered figure and cover at readable desktop and
  phone-scale sizes. Check glyphs, cropping, labels, arrows, units, legends,
  environment/version qualifiers, text contrast, and source attribution.
- Check that title, cover, caption, article, and part number refer to the same
  approved version and make the same scoped claims. Use “万字” only when the
  actual relevant article length supports it; do not describe a short part as
  a 万字 article because the unsplit mother draft was long.

## Length is measured in the actual editor

Before preparing an upload, inspect the current account's available editor and
record the date, long-form versus ordinary-note mode, title/body/image limits,
and observed count after inserting text and images. Do not confuse a short-note
caption field with the long-form body. Offline character counts are planning
estimates, not authoritative platform counts.

Historical observation, **2026-10-05**, not a permanent specification: a tested
long-form editor allowed a 64-character title and a 10,000-count body; images
also affected the count. An ordinary-note body showed a 1,000-count limit.
Recheck the actual editor each time; if inaccessible, deliver the full draft
and clearly label platform fit unverified rather than claiming it will fit.

If the approved full article exceeds the observed limit, preserve the mother
draft and ask whether to shorten or split. Present the proposed boundary and
what each part retains; do not truncate, compress away results, or publish an
extra post silently. Splitting by hardware/experiment can preserve comparison
boundaries. No fixed number of parts, sections, or images is prescribed.

After split approval, map every approved section, numerical claim, caveat, and
figure into its destination part, verify coverage, and remeasure each part in
the editor including images. Use independent titles/covers and explicit reading
order where useful. A two-part/six-image example is not a universal template.

## Authoring versus optional publication

Finish the editable files and reviewable previews without requiring a platform
login. Loading this skill or approving a blueprint does not approve uploading,
creating platform drafts, publishing, or reusing approval for future posts.
When the user requests a platform action, use
[publication QA](xiaohongshu-publication.md). If the needed tool or account is
unavailable, deliver the artifacts and state precisely which step remains.
