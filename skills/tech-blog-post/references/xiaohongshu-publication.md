# Optional Xiaohongshu publication QA

Read only when the user requests uploading, creating platform drafts, or
publishing. Use supported tools and current semantic page controls, not saved
screen coordinates. This reference provides checks, not account access or
standing authorization.

## Before changing platform state

- Verify the intended account and audience/visibility, requested action, approved
  text version, titles/covers, figure order, captions, disclosures, and any
  approved split. Preparation approval alone does not authorize submission.
  Ask when the account, content, audience, or action is ambiguous. Do not embed
  credentials or account identifiers in reusable skill files.
- Check current drafts and post management for the same article/version before
  creating another item. Inspect enough content to distinguish a revision from
  an unrelated post; do not overwrite/delete existing work without authorization.
- Confirm current editor capability and limits with the profile's dated check.
  Review any required originality/AI-content/other declarations accurately;
  never make a false declaration or silently change an approved disclosure.

## Inspect the actual composed article

Compare editor contents with the approved delivery version: complete text,
section order, numeric claims, hardware/software labels, captions, title, cover,
image count/order, legibility, visibility, and disclosures. Inspect the preview
from beginning through the final paragraph, not just the first screen. Check
for lost paragraphs, duplicated text/images, broken formulas, cropped figures,
or upload placeholders. Resolve mismatches before submission; obtain approval
for material content or scope changes.

If an upload or submission fails, times out, or has an uncertain result, inspect
the editor, draft list, and post management state before retrying. Retry only
when failure/no duplicate is established and the same action remains authorized.
If state cannot be established, stop and report uncertainty. Respect access
denials, verification gates, and platform warnings; never switch tools/accounts
or disguise content to bypass them. Use the environment's supported user handoff
when login or a required user-only action blocks progress.

## Verify and report the real outcome

A click or success toast is not proof of public availability. Distinguish
saved draft, submitted, under review, published, rejected, and unknown. Read the
post-management status and, when accessible, the actual published view; verify
correct account, title, body, figures, and visibility. Report the observed state
and time, and whether public visibility was independently confirmed.

Use only a permalink actually returned or observed for that post. Do not
construct plausible post URLs. If no verified link is available, report the
status without a fabricated link. A review-pending post remains pending; check
later only within the user's requested scope and the available tools. Never
claim success or republish solely because a link has not appeared yet.
